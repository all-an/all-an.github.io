Cache Stampede / Thundering Herd & Singleflight Rebuild

When a heavily-read cache key (e.g., homepage catalog under 10,000 req/s) expires at a single instant, thousands of threads simultaneously miss the cache and execute the same expensive SQL query, crashing the database. Coalesce concurrent in-flight misses using a Singleflight map of CompletableFuture or use Caffeine’s refreshAfterWrite to reload keys asynchronously before they expire.

// PRODUCTION-SAFE OPTION 1: Caffeine AsyncCache + refreshAfterWrite (coalesces misses automatically)
AsyncLoadingCache<UUID, ProductCatalogDto> catalogCache = Caffeine.newBuilder()
    .maximumSize(10_000)
    .refreshAfterWrite(Duration.ofMinutes(1)) // Serves slightly stale value while 1 thread reloads in background!
    .expireAfterWrite(Duration.ofMinutes(5))
    .buildAsync((catalogId, executor) -> CompletableFuture.supplyAsync(
        () -> loadCatalogFromDatabase(catalogId), executor
    ));

// PRODUCTION-SAFE OPTION 2: Explicit Singleflight coalescer for distributed Redis cache misses
private final ConcurrentHashMap<String, CompletableFuture<ProductDto>> inFlight = new ConcurrentHashMap<>();

public ProductDto getProductSingleflight(UUID id) {
    String key = "product:" + id;
    ProductDto cached = redisCache.get(key);
    if (cached != null) return cached;

    // 1,000 concurrent cache misses for the same ID share a single DB query!
    CompletableFuture<ProductDto> future = inFlight.computeIfAbsent(key, k ->
        CompletableFuture.supplyAsync(() -> {
            ProductDto fresh = productRepo.findDtoById(id);
            redisCache.set(key, fresh, Duration.ofMinutes(10));
            return fresh;
        }).whenComplete((res, ex) -> inFlight.remove(key))
    );
    return future.join();
}
