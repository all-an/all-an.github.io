Forensics & State Reconstruction via Event Sourcing & Audit Logs

When a production incident occurs ("Why is this customer’s wallet balance -$40?"), a single mutable row with updated_at cannot tell you what happened. By persisting state transitions as an immutable, versioned stream of domain events with an optimistic concurrency check on UNIQUE(aggregate_id, version), you gain both race-condition protection and a 100% replayable forensic audit trail.

// PRODUCTION-SAFE: Append-only Event Store with optimistic stream version check + deterministic replay
public sealed interface WalletEvent permits FundsDeposited, FundsWithdrawn {}
public record FundsDeposited(long amountCents, String ref) implements WalletEvent {}
public record FundsWithdrawn(long amountCents, String ref) implements WalletEvent {}

@Transactional(rollbackFor = Exception.class)
public void withdraw(UUID walletId, long amountCents, String ref) {
    List<StoredEvent> history = eventStoreRepo.loadStream(walletId);
    long currentVersion = history.size();

    // Reconstruct exact state by replaying immutable historical events
    long balance = 0;
    for (StoredEvent evt : history) {
        balance = switch (deserialize(evt)) {
            case FundsDeposited d -> balance + d.amountCents();
            case FundsWithdrawn w -> balance - w.amountCents();
        };
    }
    if (balance < amountCents) {
        throw new InsufficientFundsException("Balance " + balance + " < " + amountCents);
    }

    // UNIQUE(aggregate_id, version) constraint guarantees no concurrent event was inserted since read!
    eventStoreRepo.appendEvent(walletId, currentVersion + 1, "FundsWithdrawn",
        objectMapper.writeValueAsString(new FundsWithdrawn(amountCents, ref)));
}
