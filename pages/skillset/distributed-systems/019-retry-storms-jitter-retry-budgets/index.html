Retry Storms, Exponential Backoff with Full Jitter & Retry Budgets

If 5,000 clients fail when a database or microservice blips at t = 0 and all retry at fixed 1000ms intervals, they slam the recovering service in synchronized waves every second (a Retry Storm). Always randomize sleep intervals using Exponential Backoff with Full Jitter and cap total retries with a process-wide Retry Budget.

// PRODUCTION-SAFE: Exponential Backoff with Full Jitter + Process-Wide Retry Budget
public class ResilientRetrier {
    private static final long BASE_DELAY_MS = 100;
    private static final long MAX_DELAY_MS  = 10_000;
    // Allow at most 10% of total requests to be retries so we never amplify an outage
    private final AtomicInteger retryTokens = new AtomicInteger(100);

    public <T> T executeWithJitter(Callable<T> action, int maxAttempts) throws Exception {
        // Every normal request deposits 1 token (capped at 100); each retry withdraws 10 tokens
        retryTokens.updateAndGet(cur -> Math.min(100, cur + 1));

        for (int attempt = 1; ; attempt++) {
            try {
                return action.call();
            } catch (TransientNetworkException ex) {
                if (attempt >= maxAttempts || retryTokens.addAndGet(-10) < 0) {
                    retryTokens.updateAndGet(cur -> Math.max(0, cur));
                    throw ex; // Retry budget exhausted or max attempts reached — fail fast!
                }
                long expCap = Math.min(MAX_DELAY_MS, BASE_DELAY_MS * (1L << (attempt - 1)));
                // Full Jitter: uniform random sleep between 0 and expCap desynchronizes callers
                long sleepMs = ThreadLocalRandom.current().nextLong(0, expCap + 1);
                Thread.sleep(sleepMs);
            }
        }
    }
}
