Competing Consumers & FOR UPDATE SKIP LOCKED Work Queues

When multiple worker instances poll a relational table for pending jobs or outbox tasks, a standard SELECT ... WHERE status = 'PENDING' LIMIT 50 causes every worker to fetch the exact same 50 rows. Use FOR UPDATE SKIP LOCKED so PostgreSQL locks available rows for each worker and silently skips rows already locked by sibling workers.

// PRODUCTION-SAFE: High-throughput concurrent job claiming in PostgreSQL with SKIP LOCKED
@Transactional
public List<JobRecord> claimNextBatch(String workerId, int batchSize) {
    // Workers never block each other and never claim the same job twice
    return jdbcTemplate.query("""
        UPDATE background_jobs
        SET status = 'PROCESSING',
            locked_by = ?,
            locked_until = now() + interval '5 minutes',
            attempt_count = attempt_count + 1
        WHERE id IN (
            SELECT id
            FROM background_jobs
            WHERE (status = 'PENDING' OR (status = 'PROCESSING' AND locked_until < now()))
              AND attempt_count < max_attempts
            ORDER BY scheduled_at ASC
            FOR UPDATE SKIP LOCKED
            LIMIT ?
        )
        RETURNING id, payload_json, attempt_count
        """,
        (rs, rowNum) -> new JobRecord(
            rs.getObject("id", UUID.class),
            rs.getString("payload_json"),
            rs.getInt("attempt_count")
        ),
        workerId, batchSize
    );
}
