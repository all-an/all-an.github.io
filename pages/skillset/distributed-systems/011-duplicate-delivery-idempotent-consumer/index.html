Duplicate Message Delivery & Idempotent Consumer (Inbox Pattern)

Message brokers (Kafka, RabbitMQ, SQS) guarantee at-least-once delivery: if a consumer processes a message and crashes milliseconds before committing its offset, the broker redelivers the message. Make every consumer idempotent by inserting the message_id into a processed_messages table inside the same database transaction as the business side effect.

// PRODUCTION-SAFE: Idempotent Consumer (Inbox Table) deduplicating by unique eventId
@KafkaListener(topics = "payments.settled", groupId = "fulfillment-service")
@Transactional(rollbackFor = Exception.class)
public void onPaymentSettled(PaymentSettledEvent event) {
    // 1. Try inserting the event ID into processed_messages inside the same DB transaction
    int inserted = jdbcTemplate.update("""
        INSERT INTO processed_messages (message_id, consumer_group, processed_at)
        VALUES (?, 'fulfillment-service', now())
        ON CONFLICT (message_id, consumer_group) DO NOTHING
        """, event.eventId());

    if (inserted == 0) {
        // Duplicate delivery detected — safely acknowledge and skip side effects
        log.info("Skipping already-processed message {}", event.eventId());
        return;
    }

    // 2. Execute business mutation atomically with the inbox record
    shipmentService.scheduleShipmentForOrder(event.orderId());
}
