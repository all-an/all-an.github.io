Floating-Point Money Bugs & Minor Units (BigDecimal / Cents)

Binary floating-point types (float and double) cannot represent base-10 fractions like 0.10 exactly, causing 0.1 + 0.2 == 0.30000000000000004 and penny rounding leaks across invoices. Always store and compute monetary amounts as integer minor units (long cents) or BigDecimal constructed from strings with explicit RoundingMode.

// BROKEN: IEEE-754 double arithmetic leaks pennies and fails equality checks
double price = 19.99;
double tax   = price * 0.0725; // Unpredictable binary fraction rounding

// PRODUCTION-SAFE OPTION 1: Represent money in integer minor units (e.g. cents)
public record MoneyCents(long amountCents, String currency) {
    public MoneyCents add(MoneyCents other) {
        if (!this.currency.equals(other.currency)) throw new IllegalArgumentException("Currency mismatch");
        return new MoneyCents(Math.addExact(this.amountCents, other.amountCents), currency);
    }
}

// PRODUCTION-SAFE OPTION 2: BigDecimal from String (never new BigDecimal(double)!) + explicit RoundingMode
public static BigDecimal calculateTotalWithTax(String unitPriceStr, int quantity, String taxRateStr) {
    BigDecimal unitPrice = new BigDecimal(unitPriceStr);
    BigDecimal subtotal  = unitPrice.multiply(BigDecimal.valueOf(quantity));
    BigDecimal taxRate   = new BigDecimal(taxRateStr);
    BigDecimal tax       = subtotal.multiply(taxRate).setScale(2, RoundingMode.HALF_EVEN); // Banker's rounding
    return subtotal.add(tax).setScale(2, RoundingMode.HALF_EVEN);
}
