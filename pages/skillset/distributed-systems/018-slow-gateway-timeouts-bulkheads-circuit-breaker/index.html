Slow Third-Party Gateways, Timeouts, Bulkheads & Circuit Breakers

The most dangerous failure mode in production is not a downstream service returning HTTP 500 immediately—it is a service accepting TCP connections and hanging for 60 seconds. Without hard connect/read timeouts, a bulkhead concurrency cap, and a circuit breaker, every worker thread blocks on the slow dependency and takes down unrelated endpoints.

// PRODUCTION-SAFE: Explicit connect/read timeouts + Resilience4j Bulkhead & CircuitBreaker
@Configuration
public class HttpClientConfig {
    @Bean
    public RestClient paymentRestClient() {
        HttpClient jdkClient = HttpClient.newBuilder()
            .connectTimeout(Duration.ofMillis(1500))
            .build();
        JdkClientHttpRequestFactory factory = new JdkClientHttpRequestFactory(jdkClient);
        factory.setReadTimeout(Duration.ofMillis(3000)); // Never allow unbounded socket reads!
        return RestClient.builder().requestFactory(factory).baseUrl("https://api.psp.example").build();
    }
}

@Service
public class PaymentGatewayClient {
    @Bulkhead(name = "pspBulkhead", type = Bulkhead.Type.SEMAPHORE)
    @CircuitBreaker(name = "pspCircuitBreaker", fallbackMethod = "fallbackCharge")
    public GatewayResponse authorize(ChargeCommand cmd) {
        return paymentRestClient.post()
            .uri("/v1/charges")
            .header("Idempotency-Key", cmd.idempotencyKey())
            .body(cmd)
            .retrieve()
            .body(GatewayResponse.class);
    }

    private GatewayResponse fallbackCharge(ChargeCommand cmd, Throwable ex) {
        return GatewayResponse.queuedForAsyncRetry(cmd.idempotencyKey(), ex.getMessage());
    }
}
