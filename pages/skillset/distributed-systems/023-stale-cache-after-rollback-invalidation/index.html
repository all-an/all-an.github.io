Stale Cache After DB Rollback & Post-Commit Invalidation

If a service updates Redis inside a @Transactional method and the database transaction subsequently fails and rolls back, Redis permanently serves uncommitted phantom data. Conversely, if you evict Redis before the DB transaction commits, a concurrent reader can miss the cache and repopulate Redis with the old DB value milliseconds before commit. Always evict or update cache inside an AFTER_COMMIT listener.

// BROKEN: Evicting or writing Redis before the SQL transaction commits
@Transactional
public void updatePriceBroken(UUID productId, long newPriceCents) {
    productRepo.updatePrice(productId, newPriceCents);
    redisTemplate.delete("product:" + productId); // Concurrent reader can repopulate old DB value before commit!
}

// PRODUCTION-SAFE: Publish a domain event and evict Redis strictly AFTER_COMMIT
public record ProductPriceChangedEvent(UUID productId) {}

@Transactional(rollbackFor = Exception.class)
public void updatePriceSafe(UUID productId, long newPriceCents) {
    productRepo.updatePrice(productId, newPriceCents);
    // Registered with current transaction; only fires if the SQL transaction commits
    eventPublisher.publishEvent(new ProductPriceChangedEvent(productId));
}

@Component
public class ProductCacheInvalidator {
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void onPriceChangedAfterCommit(ProductPriceChangedEvent event) {
        redisTemplate.delete("product:" + event.productId());
    }
}
