Cross-Service Rollbacks & Saga Pattern (Orchestration + Compensation)

When a checkout spans separate Order, Inventory, and Payment microservices with isolated databases, you cannot use a single ACID transaction, and Two-Phase Commit (2PC) creates availability bottlenecks. Use a Saga Orchestrator that executes forward steps with idempotency keys and runs compensating transactions in reverse order if any step fails.

// PRODUCTION-SAFE: Saga Orchestrator with explicit backward compensating transactions
public OrderResult executeCheckoutSaga(CheckoutCommand cmd) {
    UUID sagaId = cmd.orderId();
    boolean stockReserved = false;
    boolean paymentCaptured = false;

    try {
        // Step 1: Reserve inventory (idempotent by sagaId)
        inventoryClient.reserveStock(sagaId, cmd.sku(), cmd.quantity());
        stockReserved = true;

        // Step 2: Charge customer payment method (idempotent by sagaId)
        paymentClient.capturePayment(sagaId, cmd.customerId(), cmd.amountCents());
        paymentCaptured = true;

        // Step 3: Confirm shipment & mark order completed
        shipmentClient.createShipment(sagaId, cmd.shippingAddress());
        return OrderResult.confirmed(sagaId);

    } catch (Exception ex) {
        // Backward recovery: run idempotent compensating actions in reverse order
        if (paymentCaptured) {
            safelyCompensate(() -> paymentClient.refundPayment(sagaId));
        }
        if (stockReserved) {
            safelyCompensate(() -> inventoryClient.releaseReservation(sagaId));
        }
        orderRepo.markCancelled(sagaId, ex.getMessage());
        return OrderResult.failed(sagaId, ex.getMessage());
    }
}
