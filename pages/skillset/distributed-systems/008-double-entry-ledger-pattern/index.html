Immutable Double-Entry Ledger Pattern (Debit / Credit)

In fintech and payment systems, updating a single balance = balance - 100 column destroys audit history and makes discrepancies impossible to reconcile. Instead, model money using an append-only Double-Entry Bookkeeping Ledger where every transaction inserts balanced debit and credit lines that sum to zero.

// PRODUCTION-SAFE: Append-only double-entry ledger where every transfer sums to 0
public record LedgerLine(UUID accountId, long signedAmountCents) {}

@Transactional(rollbackFor = Exception.class)
public UUID recordDoubleEntryTransfer(
        UUID idempotencyKey, UUID sourceAccountId, UUID destAccountId, long amountCents) {
    if (amountCents <= 0) throw new IllegalArgumentException("Amount must be positive");

    // 1. Lock accounts in deterministic order and verify available funds
    lockAccountsInOrder(sourceAccountId, destAccountId);
    long currentBalance = ledgerRepo.getBalanceForUpdate(sourceAccountId);
    if (currentBalance < amountCents) {
        throw new InsufficientFundsException("Available: " + currentBalance);
    }

    // 2. Insert immutable journal transaction + balanced debit (-amount) and credit (+amount) entries
    UUID journalId = UUID.randomUUID();
    ledgerRepo.insertJournal(journalId, idempotencyKey, Instant.now());
    ledgerRepo.insertEntry(journalId, sourceAccountId, -amountCents); // DEBIT
    ledgerRepo.insertEntry(journalId, destAccountId,   +amountCents); // CREDIT

    // 3. Update materialized balance cache in the same ACID transaction
    accountRepo.addBalance(sourceAccountId, -amountCents);
    accountRepo.addBalance(destAccountId,   +amountCents);
    return journalId;
}
