Flash Sale Traffic Spikes, Rate Limiting & Load Shedding

During a flash sale or ticket drop, accepting 50,000 concurrent requests into an unbounded queue causes every request to time out while the server still wastes CPU processing requests the client already abandoned. Enforce per-user Token Bucket rate limits at the edge and use a non-blocking concurrency limiter to shed excess load immediately with 503 Service Unavailable.

// PRODUCTION-SAFE: Non-blocking concurrency load shedder + per-user rate limit filter
@Component
public class LoadSheddingFilter extends OncePerRequestFilter {
    // Cap active in-flight checkout requests to match DB connection pool capacity
    private final Semaphore inFlightCheckoutPermits = new Semaphore(60);

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        if (!req.getRequestURI().startsWith("/api/v1/checkout")) {
            chain.doFilter(req, res);
            return;
        }
        // Fail fast (0ms wait) when saturated instead of queueing until OOM
        if (!inFlightCheckoutPermits.tryAcquire()) {
            res.setStatus(HttpStatus.SERVICE_UNAVAILABLE.value());
            res.setHeader("Retry-After", "2");
            res.getWriter().write("{"error":"Server at capacity, please retry shortly"}");
            return;
        }
        try {
            chain.doFilter(req, res);
        } finally {
            inFlightCheckoutPermits.release();
        }
    }
}
