Double-Click & Simultaneous Requests (Distributed Locks)

When a user double-clicks a checkout button or an external webhook fires twice across multiple Kubernetes pods, a JVM-local synchronized block offers zero protection. Use a distributed lock (e.g., Redisson RLock or PostgreSQL transaction-scoped advisory locks pg_try_advisory_xact_lock) keyed by the user or resource ID.

// OPTION 1: PostgreSQL Transaction-Scoped Advisory Lock (zero extra infrastructure, auto-released on commit/rollback)
@Transactional
public PayoutResult processPayoutWithAdvisoryLock(long merchantId, BigDecimal amount) {
    Boolean acquired = jdbcTemplate.queryForObject(
        "SELECT pg_try_advisory_xact_lock(?)", Boolean.class, merchantId
    );
    if (!Boolean.TRUE.equals(acquired)) {
        throw new ConcurrentOperationException("Payout already in progress for merchant " + merchantId);
    }
    return executePayout(merchantId, amount);
}

// OPTION 2: Redis Distributed Lock via Redisson across microservices
public PayoutResult processPayoutWithRedisLock(long merchantId, BigDecimal amount) {
    RLock lock = redissonClient.getLock("lock:payout:merchant:" + merchantId);
    try {
        if (!lock.tryLock(500, 10_000, TimeUnit.MILLISECONDS)) {
            throw new ConcurrentOperationException("Duplicate concurrent request rejected");
        }
        return executePayout(merchantId, amount);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        throw new IllegalStateException("Interrupted while acquiring lock", e);
    } finally {
        if (lock.isHeldByCurrentThread()) {
            lock.unlock();
        }
    }
}
