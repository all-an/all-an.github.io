Partial Failure Mid-Transfer, ACID Isolation & Savepoints

By default, Spring’s @Transactional only rolls back on unchecked RuntimeException and Error—meaning a thrown checked exception commits a half-finished transfer! Always set rollbackFor = Exception.class, and use JDBC/Spring Savepoint when you want a non-critical sub-step to roll back without aborting the outer transaction.

// DANGER: Spring @Transactional commits by default if a checked exception is thrown!
// PRODUCTION-SAFE: Explicitly specify rollbackFor = Exception.class
@Transactional(rollbackFor = Exception.class, isolation = Isolation.READ_COMMITTED, timeout = 5)
public TransferReceipt transferFunds(UUID fromId, UUID toId, long amountCents) throws ComplianceException {
    accountRepo.debit(fromId, amountCents);
    accountRepo.credit(toId, amountCents);

    if (complianceService.isFlagged(toId, amountCents)) {
        // Because rollbackFor = Exception.class is set, both debit and credit roll back cleanly
        throw new ComplianceException("Transfer blocked by compliance check");
    }
    return new TransferReceipt(UUID.randomUUID(), fromId, toId, amountCents);
}

// PARTIAL ROLLBACK WITH SAVEPOINT: Keep core order even if optional loyalty bonus fails
public void placeOrderWithOptionalBonus(Order order) {
    transactionTemplate.executeWithoutResult(status -> {
        orderRepo.save(order);
        Object savepoint = status.createSavepoint();
        try {
            loyaltyService.grantBonusPoints(order.getCustomerId(), order.getTotalCents());
        } catch (RuntimeException ex) {
            status.rollbackToSavepoint(savepoint); // Rolls back bonus only; order remains valid
        } finally {
            status.releaseSavepoint(savepoint);
        }
    });
}
