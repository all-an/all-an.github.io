Dual-Write Bug & Transactional Outbox Pattern

Saving an entity to PostgreSQL and calling kafkaTemplate.send(...) inside the same method is a classic Dual-Write Bug: if the DB commits and the JVM crashes before Kafka acknowledges (or if Kafka is down), downstream services never learn about the order. Insert the event into an outbox_events table inside the exact same SQL transaction, then relay it asynchronously.

// BROKEN (Dual-Write Bug): If Kafka fails after DB commit, Order exists in DB but event is lost forever!
@Transactional
public void placeOrderBroken(Order order) {
    orderRepo.save(order);
    kafkaTemplate.send("orders.events", order.getId().toString(), toEventJson(order));
}

// PRODUCTION-SAFE: Transactional Outbox Pattern — both Order and OutboxEvent commit atomically
@Transactional(rollbackFor = Exception.class)
public void placeOrderSafe(Order order) {
    orderRepo.save(order);
    OutboxEvent outbox = new OutboxEvent(
        UUID.randomUUID(),
        "Order",
        order.getId().toString(),
        "OrderCreated",
        toEventJson(order),
        Instant.now()
    );
    outboxRepo.save(outbox); // Committed in the exact same PostgreSQL transaction!
}

// Background Relay (or use Debezium CDC on the outbox_events WAL):
@Scheduled(fixedDelay = 500)
@Transactional
public void publishPendingOutboxEvents() {
    List<OutboxEvent> batch = outboxRepo.lockNextUnpublishedBatch(100); // FOR UPDATE SKIP LOCKED
    for (OutboxEvent evt : batch) {
        kafkaTemplate.send("orders.events", evt.getAggregateId(), evt.getPayload()).join();
        evt.markPublished(Instant.now());
    }
}
