G8: Too Much Information

A well-defined module has a very small interface that lets you do a lot. A poorly defined one has a wide, sprawling interface that forces you to learn a great deal just to get one thing done.
Good software hides information. Every public method, field and constant is a promise you have to keep and a coupling a caller can lean on — the more of them there are, the more of your class's insides leak into everybody else's code. The tell is a class where the helpers, the buffers and the intermediate state are all public, or an interface with a dozen methods where two would do.
Keep the interface tight: expose the intent, hide the mechanics. Fewer public members means fewer things to understand, fewer things that can be misused, and far more freedom to change what is underneath.

Avoid — every step of the mechanism is public
// Java
public class CsvReportExporter {
    public StringBuilder buffer = new StringBuilder();     // internal scratch space
    public List<String> pendingRows = new ArrayList<>();  // internal scratch space
    public char delimiter = ',';

    public String escapeField(String field) { /* ... */ }
    public String joinRow(List<String> fields) { /* ... */ }
    public void appendHeader(Report report) { /* ... */ }
    public void appendRows(Report report) { /* ... */ }
    public void flushBuffer() { /* ... */ }

    // A caller has to know this exact order to get a valid file out.
    public String result() { return buffer.toString(); }
}
Prefer — one method to call, everything else hidden
// Java
public class CsvReportExporter {
    private static final char DELIMITER = ',';

    private final StringBuilder buffer = new StringBuilder();

    // The whole interface: hand over a report, get CSV back.
    public String export(Report report) {
        appendHeader(report);
        appendRows(report);
        return buffer.toString();
    }

    private void appendHeader(Report report) { /* ... */ }

    private void appendRows(Report report) { /* ... */ }
