G5: Duplication

This is the most important rule in the book — DRY: Don't Repeat Yourself. Every time the same idea appears twice, it is a missed abstraction, and a fix applied in one copy silently leaves the other one wrong.
Duplication wears several disguises: identical lines copied around, the same switch on a type repeated in many methods, or modules with different code that solve the same problem. Each has its own cure — extract a method, replace the switch with polymorphism, hide the difference behind a common interface.
Collapse the repetition and the idea gets a name, one home, and one place to change.

Avoid — the same rule is written out once per caller
// Java
public BigDecimal invoiceTotal(Order order) {
    BigDecimal net = order.subtotal().subtract(order.discount());
    return net.add(net.multiply(new BigDecimal("0.21")));
}

public BigDecimal receiptTotal(Order order) {
    // The very same rule again; a VAT change has to be found in both places.
    BigDecimal net = order.subtotal().subtract(order.discount());
    return net.add(net.multiply(new BigDecimal("0.21")));
}
Prefer — the rule is named once and reused
// Java
private static final BigDecimal VAT_RATE = new BigDecimal("0.21"); // 21% standard rate

// The single definition of what a customer owes for an order.
private BigDecimal grossTotal(Order order) {
    BigDecimal net = order.subtotal().subtract(order.discount());
    return net.add(net.multiply(VAT_RATE));
}

public BigDecimal invoiceTotal(Order order) { return grossTotal(order); }

public BigDecimal receiptTotal(Order order) { return grossTotal(order); }
