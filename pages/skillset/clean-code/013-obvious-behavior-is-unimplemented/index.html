G2: Obvious Behavior Is Unimplemented

Following The Principle of Least Surprise, a function should do what its name leads any reader to expect. A dayNameToNumber that handles "Monday" but not "monday" or "Mon" implements only part of the behavior its name promises.
When the obvious case is missing, readers stop trusting the name and start reading the body — and every caller has to guard against the gap.
Implement what the name announces, so callers can rely on it without checking.

Avoid — the name promises more than the body delivers
// Java
public int dayNameToNumber(String dayName) {
    // Only the exact full name works; "mon", "Mon" and " Monday" all blow up.
    switch (dayName) {
        case "Monday": return 1;
        case "Tuesday": return 2;
        default: throw new IllegalArgumentException(dayName);
    }
}
Prefer — every form a reader would expect is handled
// Java
public int dayNameToNumber(String dayName) {
    // Case and surrounding spaces are noise, and the three-letter abbreviation
    // is as much a "day name" as the full word.
    String name = dayName.trim().toLowerCase();

    switch (name) {
        case "monday":  case "mon": return 1;
        case "tuesday": case "tue": return 2;
        default: throw new IllegalArgumentException(dayName);
    }
}
