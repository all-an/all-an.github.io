G11: Inconsistency

If a codebase does something a certain way in one place, do all similar things the same way everywhere else. A reader learns the pattern from the first example they see and carries it forward as an assumption — a different verb, parameter order, or structure for the same kind of operation breaks that assumption and forces them to re-learn it case by case.
This isn't about picking the "correct" convention; almost any consistent one works. It's the switching between conventions, inside the same codebase, that costs the reader time and invites mistakes.

Avoid — the same kind of lookup, named and shaped differently each time
// Java
public User getUserById(String userId) { /* ... */ }
public Order fetchOrder(String id) { /* ... */ }
public Product retrieveProductWithId(int productId) { /* ... */ }
Prefer — one verb, one parameter shape, applied everywhere
// Java
public User getUserById(String userId) { /* ... */ }
public Order getOrderById(String orderId) { /* ... */ }
public Product getProductById(String productId) { /* ... */ }
