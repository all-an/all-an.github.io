G20: Function Names Should Say What They Do, Side Effects Included

A function's name should mention every side effect it has, not just its primary return value.

Avoid — set() quietly creates the key too
boolean set(String key, String value) { /* also creates the key if missing */ }
Prefer — the name says both things it does
boolean setAndCreateIfNecessary(String key, String value) { /* ... */ }
