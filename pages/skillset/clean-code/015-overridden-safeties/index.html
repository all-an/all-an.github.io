G4: Overridden Safeties

Turning off a compiler warning, disabling a failing test or swallowing an exception buys a green build and hands the risk to production. Chernobyl started with an operator overriding a safety.
Every silenced check was a mechanism telling you something. Muting it does not make the problem go away — it makes the next reader believe there was never a problem at all.
Fix what the safety is pointing at; only then does the noise legitimately disappear.

Avoid — the safeties are switched off so the build stays green
// Java
@SuppressWarnings("unchecked") // silences the real problem: an unchecked cast
@Ignore("fails on CI, look into it later")
public void transfer(Account from, Account to, BigDecimal amount) {
    try {
        from.withdraw(amount);
        to.deposit(amount);
    } catch (InsufficientFundsException e) {
        // swallowed: the caller is told the transfer succeeded
    }
}
Prefer — the safeties stay on and the cause is fixed
// Java
public void transfer(Account from, Account to, BigDecimal amount) {
    // The caller decides what an overdrawn account means; this method only reports it.
    from.withdraw(amount);
    to.deposit(amount);
}
