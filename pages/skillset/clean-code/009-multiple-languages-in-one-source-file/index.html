G1: Multiple Languages in One Source File

A source file should speak one language. When a Java file also carries SQL, HTML and a snippet of JavaScript, the reader changes syntax and mental model line by line.
Each embedded language also loses its tooling: the compiler sees only a string, so a typo inside a quoted <script> builds fine and a concatenated SELECT invites injection.
The fix is to give every language its own file — markup in a template, SQL behind a repository — and leave the source file speaking only Java.

Avoid — Java, SQL, HTML and JavaScript in the same file
// Java
public class UserPage extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
        String sql = "SELECT name FROM users WHERE id = " + request.getParameter("id");
        String name = jdbc.queryForObject(sql, String.class);

        response.getWriter().println(
            "<div class='user'>" + name + "</div>" +
            "<script>document.querySelector('.user').classList.add('loaded')</script>");
    }
}
Prefer — one language per file, each with its own tooling
// Java
public class UserPage extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
        // The query lives in UserRepository, the markup and script in user.html.
        String name = users.nameById(request.getParameter("id"));

        response.getWriter().println(templates.render("user.html", Map.of("name", name)));
    }
}
