G3: Incorrect Behavior at the Boundaries

Code almost always works for the middle of the range. The bugs live at the edges: the empty list, the single element, the value exactly on the limit, the overflow.
Intuition is not a substitute for proof here — "it obviously works" is how off-by-one errors ship. The only proof is a test, so every boundary condition gets one of its own: the empty case, the single-element case, the value one below the limit, the value exactly on it, the value one above.
Write the edge cases first, then the implementation has nowhere to hide.

Avoid — only the happy middle was considered
// Java
public double averageOf(List<Integer> values) {
    int sum = 0;
    for (int value : values) {
        sum += value;
    }
    // Empty list divides by zero; a long list of large ints silently overflows.
    return sum / values.size();
}

@Test
public void averagesThreeNumbers() {
    assertEquals(2.0, averageOf(List.of(1, 2, 3)));
}
Prefer — the edges are handled and nailed down by tests
// Java
public double averageOf(List<Integer> values) {
    // An average of nothing is undefined — say so instead of dividing by zero.
    if (values.isEmpty()) {
        throw new IllegalArgumentException("averageOf requires at least one value");
    }

    long sum = 0; // long, so a list of large ints cannot overflow the total
    for (int value : values) {
        sum += value;
    }
    return (double) sum / values.size();
}

@Test
public void averagesThreeNumbers() {
    assertEquals(2.0, averageOf(List.of(1, 2, 3)));
}

@Test
public void rejectsAnEmptyList() {
    assertThrows(IllegalArgumentException.class, () -> averageOf(List.of()));
}

@Test
public void averagesASingleValue() {
    assertEquals(7.0, averageOf(List.of(7)));
}

@Test
public void doesNotOverflowOnLargeValues() {
    assertEquals((double) Integer.MAX_VALUE, averageOf(List.of(Integer.MAX_VALUE, Integer.MAX_VALUE)));
}
