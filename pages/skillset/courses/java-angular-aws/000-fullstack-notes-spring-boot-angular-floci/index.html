Full-Stack Notes App: Spring Boot, Angular & AWS on Floci

Fullstack

A small full-stack app built the way you'd build it for AWS, without an AWS account. A Spring Boot API stores notes in DynamoDB, keeps attachments in S3 and announces new notes on SQS; an Angular app is the front end; and Floci, a free local AWS emulator running in Docker, stands in for AWS. It all ends in one docker compose up.

Step 1 — Verify your toolchain (Docker, Java & Node)

This course builds a real full-stack app and runs the "cloud" part on your own machine, so you need three tools: Docker (with Compose v2), a JDK 21 for the Spring Boot API, and Node 20+ for the Angular CLI. Maven isn't on the list — the generated Spring Boot project ships its own wrapper (./mvnw) — and neither is the AWS CLI: it runs as a container too (Step 3).

docker --version
docker compose version
java -version
node --version
npm --version

Each should print a version banner. If one is missing: install Docker Desktop (it includes Compose), a JDK through SDKMAN (sdk install java 21-tem), and Node through nvm. The Angular CLI itself is fetched on demand in Step 15, so there's nothing to install globally.

You don't need an AWS account

Every AWS call in this course goes to Floci, a free, open-source AWS emulator that runs in a single Docker container and listens on one port. It accepts any non-empty access key and secret, so there's no account, no billing, no token and no internet needed once the images are pulled. The Java code you write is the same code you'd ship against real AWS — only the endpoint URL and the credentials change.

Step 2 — The project: Notebook, and how the pieces fit

We'll build Notebook: a small notes app. You write a note in the browser, optionally attach a file to it, and see a word count appear a moment later. It's deliberately small, but it touches the three AWS services most real apps start with:

DynamoDB stores the notes. S3 stores the attachments. SQS carries a "note created" message from the request that made the note to a background poller, which counts the words and writes the result back — the smallest honest example of asynchronous work.

:4200   /api      :8080
                              ──▶ S3         (attachments)
                              ──▶ SQS        (note-events)
                                   │
                                   ▼
                              poller ──▶ DynamoDB (word count)

Step 3 — Run AWS locally: Floci in Docker

Create compose.yaml in the project root. Floci's image is floci/floci and everything — S3, DynamoDB, SQS and a hundred other services — is served on port 4566. Next to it goes a second service: the AWS CLI as a container (amazon/aws-cli), already pointed at Floci with the fake credentials, so you never install the CLI on your machine. It sits in a tools profile, which keeps it from starting with the stack — you only run it on demand:

# the AWS CLI as a container: already pointed at Floci, nothing to install
x-aws-cli: &aws-cli
  image: amazon/aws-cli
  depends_on:
    - floci
  environment:
    AWS_ENDPOINT_URL: http://floci:4566
    AWS_DEFAULT_REGION: us-east-1
    AWS_ACCESS_KEY_ID: test
    AWS_SECRET_ACCESS_KEY: test
  volumes:
    - ./scripts:/scripts:ro

services:
  floci:
    image: floci/floci:latest
    ports:
      - "4566:4566"
    environment:
      FLOCI_DEFAULT_REGION: us-east-1

  aws:
    <<: *aws-cli
    profiles: ["tools"]
docker compose up -d floci
docker compose logs floci

The logs should show Floci starting and listening on 4566. Now talk to it with the AWS CLI container. Running a command is docker compose run --rm aws <command>; wrap that in an alias so the rest of the course reads like normal AWS commands:

alias aws='docker compose run --rm aws'

aws s3 ls

The first run pulls the amazon/aws-cli image. Empty output with no error means the emulator answered: you have no buckets yet, which is correct. If you get a connection error, check docker compose ps shows Floci as running.

About that alias

An alias only lives in the terminal where you typed it, and the command it expands to must be run from the project root, where compose.yaml is — so define it again in any new terminal. --rm deletes the throwaway container after each command. On Windows PowerShell use function aws { docker compose run --rm aws @args } instead. Because the CLI runs inside the Compose network it reaches Floci as floci:4566, which is why the compose file sets AWS_ENDPOINT_URL to that rather than localhost.

Why Floci, and what "memory" storage means

Floci is a lighter, always-free alternative to running something like LocalStack: a small image, one port, no auth token. By default it keeps everything in memory (FLOCI_STORAGE_MODE=memory; persistent, hybrid and wal modes also exist), so stopping the container throws the data away. That's fine for development and tests, and it's why Step 4 puts resource creation in a script you can re-run any time. Floci's source and docs live at github.com/floci-io/floci.

Step 4 — Create the S3 bucket, DynamoDB table and SQS queue

Put the three resources in one idempotent script so you can recreate them whenever Floci restarts. It waits until Floci answers, then creates a bucket for attachments, a table keyed by id for the notes, and the queue the API will publish to. Save it as scripts/init-aws.sh:

#!/bin/sh
# Creates the AWS resources Notebook needs. Safe to run again: anything that
# already exists is left alone. Reads the endpoint and credentials from the
# AWS_* environment variables set on the aws container.
set -e

# Floci takes a moment to start; wait until it answers.
until aws s3 ls >/dev/null 2>&1; do
  echo "waiting for floci..."
  sleep 1
done

aws s3 mb s3://notebook-attachments || true

aws dynamodb create-table \
  --table-name notes \
  --attribute-definitions AttributeName=id,AttributeType=S \
  --key-schema AttributeName=id,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST || true

aws sqs create-queue --queue-name note-events

echo "floci is ready".

Run it inside the AWS CLI container (the endpoint and credentials come from its environment, and ./scripts is mounted at /scripts), then look at what it made:

docker compose run --rm --entrypoint sh aws /scripts/init-aws.sh

aws s3 ls
aws dynamodb list-tables
aws sqs list-queues

You should see notebook-attachments, a TableNames list containing notes, and a QueueUrls list with an address ending in /note-events. These are the three names the Spring Boot configuration will use in Step 7.

DynamoDB only needs the key up front

A DynamoDB table declares only its key attributes; every other attribute (title, body, wordCount ...) is just stored on the item and can differ between items. That's why the script lists a single id attribute of type string (S) as the hash key and nothing else. PAY_PER_REQUEST avoids having to specify read/write capacity, which an emulator ignores anyway.

Step 5 — Generate the Spring Boot project

start.spring.io can be driven from the command line. From the project root, download a Maven project with Java 21 and three starters: web (the REST API), validation (request checks) and actuator (a health endpoint). Unzip it into backend/:

curl https://start.spring.io/starter.zip -o backend.zip \
  -d type=maven-project -d language=java -d javaVersion=21 \
  -d groupId=dev.notebook -d artifactId=notebook-api -d name=notebook-api \
  -d packageName=dev.notebook.api \
  -d dependencies=web,validation,actuator

unzip backend.zip -d backend && rm backend.zip
cd backend
./mvnw -q compile

The last command downloads the dependencies and compiles the empty app — no output means it built. Everything we add from here lives under backend/src/main/java/dev/notebook/api/, all in that one package so the classes can see each other without ceremony.

Why one package, and no Lombok

A real service would split into web, service and persistence packages. Keeping a single package keeps this course's files short and its imports minimal. Lombok is left out on purpose: the DynamoDB enhanced client needs plain JavaBeans, and seeing the getters and setters once makes it obvious what the mapper is reading.

Why dynamodb-enhanced and not just dynamodb

The low-level dynamodb module makes you build maps of AttributeValue by hand. dynamodb-enhanced (which pulls the low-level module in) maps a Java bean to an item for you: annotate a class, get a typed putItem, getItem and scan. It's what Step 9 and Step 10 use.

Step 7 — Configuration: application.yml and typed properties

Every value that differs between your laptop and real AWS — the endpoint, credentials and resource names — goes in configuration, not code. Delete the generated src/main/resources/application.properties and create application.yml next to it:

spring:
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 10MB

app:
  aws:
    # leave endpoint out to talk to real AWS
    endpoint: http://localhost:4566
    region: us-east-1
    access-key: test
    secret-key: test
    bucket: notebook-attachments
    table: notes
    queue: note-events

Bind the app.aws section to a Java record. Spring Boot fills a record's constructor from the matching properties, giving you a typed, immutable settings object instead of scattered @Value strings. AwsProperties.java:

package dev.notebook.api;

import org.springframework.boot.context.properties.ConfigurationProperties;

// The app.aws.* section of application.yml, as one typed object.
@ConfigurationProperties(prefix = "app.aws")
public record AwsProperties(
        String endpoint,
        String region,
        String accessKey,
        String secretKey,
        String bucket,
        String table,
        String queue) {
}

Tell Spring to find it, and turn on scheduling now (Step 13's queue poller needs it). Replace the generated NotebookApiApplication.java:

import org.springframework.boot.context.properties.ConfigurationPropertiesScan;

@SpringBootApplication
@ConfigurationPropertiesScan

    public static void main(String[] args) {
        SpringApplication.run(NotebookApiApplication.class, args);

Why test/test are fine as credentials

The AWS SDK refuses to build a client without credentials, but Floci doesn't check them — any non-empty pair is accepted. Real deployments never put keys in application.yml; they rely on the SDK's default credential chain (an IAM role, environment variables or a profile). The next step makes that switch a one-liner.

Step 8 — The AWS clients, pointed at Floci

Three SDK clients — S3, DynamoDB and SQS — each built the same way: an endpoint override (Floci's address instead of AWS's), a region, and the static test credentials. Create AwsConfig.java:

package dev.notebook.api;

import java.net.URI;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import software.amazon.awssdk.auth.credentials.AwsBasicCredentials;
import software.amazon.awssdk.auth.credentials.StaticCredentialsProvider;
import software.amazon.awssdk.enhanced.dynamodb.DynamoDbEnhancedClient;
import software.amazon.awssdk.regions.Region;
import software.amazon.awssdk.services.dynamodb.DynamoDbClient;
import software.amazon.awssdk.services.s3.S3Client;
import software.amazon.awssdk.services.sqs.SqsClient;

// Builds the three AWS clients the app uses. Every one is pointed at the
// endpoint in application.yml, which is Floci locally.
@Configuration
public class AwsConfig {

    private final AwsProperties props;

    public AwsConfig(AwsProperties props) {
        this.props = props;
    }

    private StaticCredentialsProvider credentials() {
        return StaticCredentialsProvider.create(
                AwsBasicCredentials.create(props.accessKey(), props.secretKey()));
    }

    @Bean
    public S3Client s3Client() {
        return S3Client.builder()
                .endpointOverride(URI.create(props.endpoint()))
                .region(Region.of(props.region()))
                .credentialsProvider(credentials())
                .forcePathStyle(true) // http://host/bucket/key, not http://bucket.host/key
                .build();
    }

    @Bean
    public DynamoDbClient dynamoDbClient() {
        return DynamoDbClient.builder()
                .endpointOverride(URI.create(props.endpoint()))
                .region(Region.of(props.region()))
                .credentialsProvider(credentials())
                .build();
    }

    @Bean
    public DynamoDbEnhancedClient dynamoDbEnhancedClient(DynamoDbClient dynamoDbClient) {
        return DynamoDbEnhancedClient.builder().dynamoDbClient(dynamoDbClient).build();
    }

    @Bean
    public SqsClient sqsClient() {
        return SqsClient.builder()
                .endpointOverride(URI.create(props.endpoint()))
                .region(Region.of(props.region()))
                .credentialsProvider(credentials())
                .build();
    }
}
forcePathStyle, and how to go to real AWS later

Real S3 uses virtual-hosted addresses like my-bucket.s3.amazonaws.com, which needs wildcard DNS. An emulator on localhost or floci has no such DNS, so forcePathStyle(true) puts the bucket in the path instead. To run the same code against real AWS you'd drop the three endpointOverride lines, remove the static credentials provider (so the SDK's default credential chain takes over), and leave forcePathStyle off — nothing else in the app changes.

Step 9 — The Note model, as a DynamoDB bean

The enhanced client maps a plain JavaBean to a table row. The class must be public, have a no-argument constructor, getters and setters for every attribute, and mark which getter is the partition key. Note.java:

package dev.notebook.api;

import java.time.Instant;

import software.amazon.awssdk.enhanced.dynamodb.mapper.annotations.DynamoDbBean;
import software.amazon.awssdk.enhanced.dynamodb.mapper.annotations.DynamoDbPartitionKey;

// One row of the "notes" table.
@DynamoDbBean
public class Note {

    private String id;
    private String title;
    private String body;
    private int wordCount;
    private String attachmentKey;   // the S3 object key, or null
    private String attachmentName;  // the original file name, for display
    private String attachmentType;  // the MIME type, for downloads
    private Instant createdAt;

    @DynamoDbPartitionKey
    public String getId() { return id; }
    public void setId(String id) { this.id = id; }

    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }

    public String getBody() { return body; }
    public void setBody(String body) { this.body = body; }

    public int getWordCount() { return wordCount; }
    public void setWordCount(int wordCount) { this.wordCount = wordCount; }

    public String getAttachmentKey() { return attachmentKey; }
    public void setAttachmentKey(String attachmentKey) { this.attachmentKey = attachmentKey; }

    public String getAttachmentName() { return attachmentName; }
    public void setAttachmentName(String attachmentName) { this.attachmentName = attachmentName; }

    public String getAttachmentType() { return attachmentType; }
    public void setAttachmentType(String attachmentType) { this.attachmentType = attachmentType; }

    public Instant getCreatedAt() { return createdAt; }
    public void setCreatedAt(Instant createdAt) { this.createdAt = createdAt; }
}

The same class doubles as the JSON the API returns — Jackson reads the getters — so the Angular app in Step 16 will see exactly these field names.

Step 10 — NoteRepository: DynamoDB reads and writes

The repository is the only class that knows the notes live in DynamoDB. It asks the enhanced client for a typed DynamoDbTable<Note> — the table name from configuration, the schema derived from the bean's annotations — and exposes four plain methods. NoteRepository.java:

package dev.notebook.api;

import java.time.Instant;
import java.util.Comparator;
import java.util.List;
import java.util.Optional;

import org.springframework.stereotype.Repository;

import software.amazon.awssdk.enhanced.dynamodb.DynamoDbEnhancedClient;
import software.amazon.awssdk.enhanced.dynamodb.DynamoDbTable;
import software.amazon.awssdk.enhanced.dynamodb.Key;
import software.amazon.awssdk.enhanced.dynamodb.TableSchema;

// Stores notes in the DynamoDB table named in application.yml.
@Repository
public class NoteRepository {

    private final DynamoDbTable<Note> table;

    public NoteRepository(DynamoDbEnhancedClient client, AwsProperties props) {
        this.table = client.table(props.table(), TableSchema.fromBean(Note.class));
    }

    public void save(Note note) {
        table.putItem(note); // inserts, or replaces the item with the same id
    }

    public Optional<Note> findById(String id) {
        return Optional.ofNullable(table.getItem(key(id)));
    }

    // A scan reads the whole table: fine for a notebook, wrong for millions
    // of rows (a real design would query an index instead).
    public List<Note> findAll() {
        return table.scan().items().stream()
                .sorted(Comparator.comparing(Note::getCreatedAt, Comparator.nullsLast(Comparator.<Instant>reverseOrder())))
                .toList();
    }

    public void delete(String id) {
        table.deleteItem(key(id));
    }

    private Key key(String id) {
        return Key.builder().partitionValue(id).build();
    }
}
putItem replaces the whole item

putItem writes the entire bean over whatever was stored under that id. That's simple and correct here, but it means two writers that each read, change and save the same note can overwrite each other's change. Step 13 has exactly that situation (the poller and an attachment upload), and it's called out there.

Step 11 — The service and the REST controller

First the request body for creating a note, with validation on it, a record again. CreateNoteRequest.java:

package dev.notebook.api;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;

// The JSON body of POST /api/notes.
public record CreateNoteRequest(
        @NotBlank @Size(max = 120) String title,
        @Size(max = 4000) String body) {
}

A missing note should be a 404, not a 500. An exception annotated with @ResponseStatus does that with no handler code. NoteNotFoundException.java:

package dev.notebook.api;

import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.ResponseStatus;

@ResponseStatus(HttpStatus.NOT_FOUND)
public class NoteNotFoundException extends RuntimeException {

    public NoteNotFoundException(String id) {
        super("No note with id " + id);
    }
}

The service holds the rules: ids and timestamps are assigned here, and deleting a note also removes its file. It depends on two classes we write in the next steps — AttachmentStore (S3) and NoteEvents (SQS) — so the project won't compile again until Step 13. That's expected. NoteService.java:

package dev.notebook.api;

import java.io.IOException;
import java.time.Instant;
import java.util.List;
import java.util.UUID;

import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;
import org.springframework.web.multipart.MultipartFile;

@Service
public class NoteService {

    private final NoteRepository notes;
    private final AttachmentStore attachments;
    private final NoteEvents events;

    public NoteService(NoteRepository notes, AttachmentStore attachments, NoteEvents events) {
        this.notes = notes;
        this.attachments = attachments;
        this.events = events;
    }

    public List<Note> list() {
        return notes.findAll();
    }

    public Note get(String id) {
        return notes.findById(id).orElseThrow(() -> new NoteNotFoundException(id));
    }

    public Note create(CreateNoteRequest request) {
        Note note = new Note();
        note.setId(UUID.randomUUID().toString());
        note.setTitle(request.title());
        note.setBody(request.body() == null ? "" : request.body());
        note.setCreatedAt(Instant.now());
        notes.save(note);
        events.noteCreated(note.getId()); // the poller will count the words
        return note;
    }

    public void delete(String id) {
        Note note = get(id);
        if (note.getAttachmentKey() != null) {
            attachments.delete(note.getAttachmentKey());
        }
        notes.delete(id);
    }

    public Note attach(String id, MultipartFile file) throws IOException {
        Note note = get(id);
        if (note.getAttachmentKey() != null) {
            attachments.delete(note.getAttachmentKey()); // replacing: drop the old file
        }
        String name = StringUtils.cleanPath(file.getOriginalFilename() == null ? "attachment" : file.getOriginalFilename());
        String type = file.getContentType() == null ? "application/octet-stream" : file.getContentType();
        String key = id + "/" + name;

        attachments.put(key, type, file.getBytes());
        note.setAttachmentKey(key);
        note.setAttachmentName(name);
        note.setAttachmentType(type);
        notes.save(note);
        return note;
    }
}

And the controller: five routes under /api/notes, thin on purpose. NoteController.java:

package dev.notebook.api;

import java.io.IOException;
import java.util.List;

import org.springframework.http.ContentDisposition;
import org.springframework.http.HttpHeaders;
import org.springframework.http.HttpStatus;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.multipart.MultipartFile;

import jakarta.validation.Valid;

@RestController
@RequestMapping("/api/notes")
public class NoteController {

    private final NoteService service;
    private final AttachmentStore attachments;

    public NoteController(NoteService service, AttachmentStore attachments) {
        this.service = service;
        this.attachments = attachments;
    }

    @GetMapping
    public List<Note> list() {
        return service.list();
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public Note create(@Valid @RequestBody CreateNoteRequest request) {
        return service.create(request);
    }

    @GetMapping("/{id}")
    public Note get(@PathVariable String id) {
        return service.get(id);
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void delete(@PathVariable String id) {
        service.delete(id);
    }

    @PostMapping("/{id}/attachment")
    public Note upload(@PathVariable String id, @RequestParam("file") MultipartFile file) throws IOException {
        return service.attach(id, file);
    }

    @GetMapping("/{id}/attachment")
    public ResponseEntity<byte[]> download(@PathVariable String id) {
        Note note = service.get(id);
        if (note.getAttachmentKey() == null) {
            return ResponseEntity.notFound().build();
        }
        byte[] data = attachments.get(note.getAttachmentKey());
        return ResponseEntity.ok()
                .contentType(MediaType.parseMediaType(note.getAttachmentType()))
                .header(HttpHeaders.CONTENT_DISPOSITION,
                        ContentDisposition.inline().filename(note.getAttachmentName()).build().toString())
                .body(data);
    }
}
Why the controller returns the Note bean directly

For a course this size, returning the DynamoDB bean as the JSON response keeps one class instead of two. In a larger service you'd add a separate response record so the storage shape (like attachmentKey, an internal S3 key) isn't part of the public API.

Step 12 — Attachments in S3

Another small class owns everything S3: put an object, get it back, delete it. The bucket name comes from configuration. AttachmentStore.java:

package dev.notebook.api;

import org.springframework.stereotype.Component;

import software.amazon.awssdk.core.sync.RequestBody;
import software.amazon.awssdk.services.s3.S3Client;
import software.amazon.awssdk.services.s3.model.DeleteObjectRequest;
import software.amazon.awssdk.services.s3.model.GetObjectRequest;
import software.amazon.awssdk.services.s3.model.PutObjectRequest;

// Stores note attachments as objects in the S3 bucket named in application.yml.
@Component
public class AttachmentStore {

    private final S3Client s3;
    private final String bucket;

    public AttachmentStore(S3Client s3, AwsProperties props) {
        this.s3 = s3;
        this.bucket = props.bucket();
    }

    public void put(String key, String contentType, byte[] data) {
        s3.putObject(PutObjectRequest.builder()
                .bucket(bucket).key(key).contentType(contentType).build(),
                RequestBody.fromBytes(data));
    }

    public byte[] get(String key) {
        return s3.getObjectAsBytes(GetObjectRequest.builder()
                .bucket(bucket).key(key).build()).asByteArray();
    }

    public void delete(String key) {
        s3.deleteObject(DeleteObjectRequest.builder().bucket(bucket).key(key).build());
    }
}

Keys look like <note id>/<file name>, so every note's files share a "folder" prefix. S3 has no real folders — a key is just a string — but the slash makes aws s3 ls --recursive read nicely.

Streaming through the API vs presigned URLs

Here the browser downloads through the API, which fetches the object into memory and returns it. That's the simplest thing that works and is fine for small files. The production pattern is a presigned URL: the API asks S3 to sign a short-lived link and hands it to the browser, which then downloads straight from S3 without the file ever passing through your server. The SDK's S3Presigner does this, and it works against Floci too — a good follow-up exercise.

Step 13 — Events with SQS: a producer and a poller

The producer sends the id of every new note to the queue. The queue's URL is what SQS calls need, so it's looked up by name. NoteEvents.java:

package dev.notebook.api;

import org.springframework.stereotype.Component;

import software.amazon.awssdk.services.sqs.SqsClient;
import software.amazon.awssdk.services.sqs.model.GetQueueUrlRequest;
import software.amazon.awssdk.services.sqs.model.SendMessageRequest;

// Publishes "a note was created" messages to the SQS queue.
@Component
public class NoteEvents {

    private final SqsClient sqs;
    private final String queueName;

    public NoteEvents(SqsClient sqs, AwsProperties props) {
        this.sqs = sqs;
        this.queueName = props.queue();
    }

    // SQS addresses a queue by URL, not by name; ask for it when needed.
    String queueUrl() {
        return sqs.getQueueUrl(GetQueueUrlRequest.builder().queueName(queueName).build()).queueUrl();
    }

    public void noteCreated(String noteId) {
        sqs.sendMessage(SendMessageRequest.builder()
                .queueUrl(queueUrl()).messageBody(noteId).build());
    }
}

The consumer is a scheduled method that asks the queue for messages every couple of seconds. For each id it loads the note, counts the words, saves it back and then deletes the message — deleting last means a crash mid-way makes SQS deliver the message again instead of losing it. NoteEventPoller.java:

package dev.notebook.api;

import java.util.List;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

import software.amazon.awssdk.core.exception.SdkException;
import software.amazon.awssdk.services.sqs.SqsClient;
import software.amazon.awssdk.services.sqs.model.DeleteMessageRequest;
import software.amazon.awssdk.services.sqs.model.Message;
import software.amazon.awssdk.services.sqs.model.ReceiveMessageRequest;

// Background worker: turns "note created" messages into a word count.
@Component
public class NoteEventPoller {

    private static final Logger log = LoggerFactory.getLogger(NoteEventPoller.class);

    private final SqsClient sqs;
    private final NoteEvents events;
    private final NoteRepository notes;

    public NoteEventPoller(SqsClient sqs, NoteEvents events, NoteRepository notes) {
        this.sqs = sqs;
        this.events = events;
        this.notes = notes;
    }

    @Scheduled(fixedDelay = 2000)
    void poll() {
        try {
            String queueUrl = events.queueUrl();
            List<Message> messages = sqs.receiveMessage(ReceiveMessageRequest.builder()
                    .queueUrl(queueUrl).maxNumberOfMessages(10).waitTimeSeconds(1).build()).messages();
            for (Message message : messages) {
                countWords(message.body());
                sqs.deleteMessage(DeleteMessageRequest.builder()
                        .queueUrl(queueUrl).receiptHandle(message.receiptHandle()).build());
            }
        } catch (SdkException e) {
            // Floci not up yet, or the queue not created yet: try again next tick.
            log.warn("Could not poll the queue: {}", e.getMessage());
        }
    }

    private void countWords(String noteId) {
        notes.findById(noteId).ifPresent(note -> {
            String body = note.getBody();
            note.setWordCount(body == null || body.isBlank() ? 0 : body.trim().split("\\s+").length);
            notes.save(note);
            log.info("Counted {} words for note {}", note.getWordCount(), noteId);
        });
    }
}
A lost-update bug hiding in plain sight

countWords reads the note, changes one field and saves the whole note back. If a user attaches a file in the milliseconds between that read and that save, the save overwrites the new attachment fields with the old (empty) ones. For a notebook the window is tiny, but it's a real race. The fix is to update only the attribute you own — the enhanced client's updateItem with ignoreNulls(true) on a copy that carries just the id and the word count — or to keep the word count in a separate table. Worth knowing before you copy this pattern into something that matters.

Why a message body and not the whole note

The message carries only the note's id. The consumer loads the current note itself, so it always works on fresh data and the message stays tiny. Queues are for telling a worker that something happened; the database remains the source of truth for what the data is.

2. A dev proxy. The page is served from localhost:4200 and the API lives on localhost:8080; the browser would block those cross-origin calls. Instead of adding CORS code to the API, let the Angular dev server forward anything under /api. Create proxy.conf.json next to package.json:

{
  "/api": {
    "target": "http://localhost:8080",
    "secure": false
  }
}

Then make npm start use it by changing the start script in package.json:

"scripts": {
  "start": "ng serve --proxy-config proxy.conf.json"
}
Why a proxy instead of CORS

With the proxy the browser only ever talks to localhost:4200, so there is no cross-origin request and nothing to configure on the API. And it's the same shape production uses: in Step 21 nginx serves the Angular files and forwards /api to the API, so the front-end code (which just calls /api/notes) is identical in development and in Docker.

Step 16 — The Note model and NotesService

A TypeScript interface describing exactly what the API returns (the field names are the Java getters from Step 9). Create src/app/note.model.ts:

export interface Note {

  title: string;
  body: string;
  wordCount: number;

And one injectable service that is the only place that knows the URLs. Each method returns an Observable; the component decides when to subscribe. src/app/notes.service.ts:

import { HttpClient } from '@angular/common/http';
import { Injectable, inject } from '@angular/core';
import { Observable } from 'rxjs';
import { Note } from './note.model';

@Injectable({ providedIn: 'root' })
export class NotesService {
  private readonly http = inject(HttpClient);

  list(): Observable<Note[]> {
    return this.http.get<Note[]>('/api/notes');
  }

  create(title: string, body: string): Observable<Note> {
    return this.http.post<Note>('/api/notes', { title, body });
  }

  remove(id: string): Observable<void> {
    return this.http.delete<void>(`/api/notes/${id}`);
  }

  // multipart/form-data with a single "file" part, matching @RequestParam("file")
  attach(id: string, file: File): Observable<Note> {
    const form = new FormData();
    form.append('file', file);
    return this.http.post<Note>(`/api/notes/${id}/attachment`, form);
  }

  attachmentUrl(id: string): string {
    return `/api/notes/${id}/attachment`;
  }
}
Don't set Content-Type for the upload yourself

When you pass a FormData to HttpClient, the browser writes the multipart/form-data header including its random boundary string. Setting that header by hand is the classic way to break uploads, because your header won't contain the boundary.

Step 17 — The notes page component

One component for the whole screen. All its state is signals, which keeps it correct whether the app runs with zone.js or zoneless: setting a signal always schedules a re-render, while assigning a plain field inside an async callback might not. src/app/notes-page.ts:

import { DatePipe } from '@angular/common';
import { Component, OnInit, inject, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { Note } from './note.model';
import { NotesService } from './notes.service';

const COUNT_REFRESH_DELAY_MS = 2500; // the word count arrives asynchronously, via SQS

@Component({
  selector: 'app-notes-page',
  imports: [FormsModule, DatePipe],
  templateUrl: './notes-page.html',
  styleUrl: './notes-page.css',
})
export class NotesPage implements OnInit {
  private readonly notesService = inject(NotesService);

  protected readonly notes = signal<Note[]>([]);
  protected readonly error = signal<string | null>(null);
  protected readonly title = signal('');
  protected readonly body = signal('');

  ngOnInit(): void {
    this.refresh();
  }

  protected refresh(): void {
    this.notesService.list().subscribe({
      next: (notes) => {
        this.notes.set(notes);
        this.error.set(null);
      },
      error: () => this.error.set('Could not reach the API. Is it running on :8080?'),
    });
  }

  protected add(): void {
    const title = this.title().trim();
    if (!title) return;
    this.notesService.create(title, this.body()).subscribe(() => {
      this.title.set('');
      this.body.set('');
      this.refresh();
      // The poller fills in the word count a moment later; look again then.
      setTimeout(() => this.refresh(), COUNT_REFRESH_DELAY_MS);
    });
  }

  protected remove(note: Note): void {
    this.notesService.remove(note.id).subscribe(() => this.refresh());
  }

  protected upload(note: Note, event: Event): void {
    const file = (event.target as HTMLInputElement).files?.[0];
    if (!file) return;
    this.notesService.attach(note.id, file).subscribe(() => this.refresh());
  }

  protected attachmentUrl(note: Note): string {
    return this.notesService.attachmentUrl(note.id);
  }
}

The root component only has to show it. Open src/app/app.ts — in Angular 19 and earlier the file is app.component.ts and the class AppComponent — and reduce it to:

*.iml

Why the endpoint isn't baked in

The image has no idea where AWS is. Inside Compose the API will reach Floci at http://floci:4566, not localhost, and Spring Boot lets an environment variable override any property: APP_AWS_ENDPOINT overrides app.aws.endpoint. Step 22 sets it. The same image could therefore point at real AWS just by dropping that variable and the static credentials.

Step 22 — One command: the whole stack in Compose

Now grow compose.yaml into the whole stack. Floci gets FLOCI_HOSTNAME (it writes its own address into things like SQS queue URLs, and the API in another container needs to be given an address it can actually reach). The aws-init service reuses the AWS CLI definition from Step 3 as a one-shot container that runs the Step 4 script; the API waits for it to finish, and the front end waits for the API:

x-aws-cli: &aws-cli
  image: amazon/aws-cli
  depends_on:
    - floci
  environment:
    AWS_ENDPOINT_URL: http://floci:4566
    AWS_DEFAULT_REGION: us-east-1
    AWS_ACCESS_KEY_ID: test
    AWS_SECRET_ACCESS_KEY: test
  volumes:
    - ./scripts:/scripts:ro

services:
  floci:
    image: floci/floci:latest
    ports:
      - "4566:4566"
    environment:
      FLOCI_DEFAULT_REGION: us-east-1
      FLOCI_HOSTNAME: floci

  # on demand only: docker compose run --rm aws s3 ls
  aws:
    <<: *aws-cli
    profiles: ["tools"]

  # runs once at startup and exits
  aws-init:
    <<: *aws-cli
    entrypoint: ["sh", "/scripts/init-aws.sh"]

  backend:
    build: ./backend
    depends_on:
      aws-init:
        condition: service_completed_successfully
    environment:
      APP_AWS_ENDPOINT: http://floci:4566
    ports:
      - "8080:8080"

  frontend:
    build: ./frontend
    depends_on:
      - backend
    ports:
      - "4200:80"
docker compose up --build

The first build downloads Maven and Node dependencies and takes a few minutes; later runs are cached. Watch the order in the logs: Floci starts, aws-init prints floci is ready and exits, the API starts and its poller begins ticking, then nginx comes up. Open http://localhost:4200 — it is the same app as Step 19, now with every piece in a container.

Stop everything with Ctrl-C, and remove the containers with:

docker compose down
What FLOCI_HOSTNAME is for

When you create a queue, SQS returns its URL, which includes a host name. If Floci thought its own name was localhost, the API container would be handed http://localhost:4566/... — and inside the API container, localhost is the API itself. Setting FLOCI_HOSTNAME: floci makes Floci hand out http://floci:4566/..., which resolves to the right container on the Compose network. The aws alias keeps working too, since the CLI container is on the same network as Floci.

Why aws-init instead of creating resources in Java

The API could create its own bucket, table and queue at startup, and plenty of apps do. Keeping it in a script mirrors how real AWS resources get created — outside the application, by infrastructure code — and the same script works for the host, for CI and for this Compose file.

What each piece taught

Floci + Docker: a free, disposable AWS for development and tests. Spring Boot: typed configuration, three SDK clients, a thin controller over a service over a repository. DynamoDB / S3 / SQS: a table, an object store and a queue — the three services most real systems start with. Angular: a typed service, a signal-based component and the built-in control flow. Docker Compose: ordering containers (init job, API, front end) and giving them addresses that resolve inside the network.

Taking it to real AWS

The code is already shaped for it. Remove the endpoint property (and the three endpointOverride lines), drop the static credentials so the SDK uses its default chain (an IAM role in ECS, EC2 or Lambda; environment variables or an SSO profile locally), create the bucket, table and queue with infrastructure code instead of init-aws.sh, and switch S3 downloads to presigned URLs. Nothing about the controllers, the service or the Angular app changes.
