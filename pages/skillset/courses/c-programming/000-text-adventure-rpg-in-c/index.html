Text Adventure RPG in C

Concepts

A step-by-step build of a text adventure RPG in C — every step introduces one more C feature, in the order you'll actually reach for it while writing the game.

Step 1 — Verify your toolchain (gcc & gdb)

Before writing a single line of the game, confirm the compiler and debugger you'll use for the rest of this course are installed and on your PATH.

gcc --version
gdb --version

You should see a version banner for each, for example gcc (Ubuntu 13.2.0) 13.2.0 and GNU gdb (Ubuntu 12.1) 12.1. If either command isn't found, install the standard build tools for your platform first — build-essential on Debian/Ubuntu, Xcode Command Line Tools on macOS, or MinGW/WSL on Windows — then re-run both commands.

We'll use gcc to compile every step, and gdb very soon, when we start hunting real bugs in Step 3.

Step 2 — Hello, World in C

Every C program starts the same way: an entry point named main. Create a file called hello.c with the following contents.

#include <stdio.h>
#include <string.h>

// Prints the game's opening greeting.
void greet(void) {
    printf("Hello, World!\n");
}

// Hand-rolled unit test for greet(). No framework, no separate file —
// every step's tests live right next to the code they check, and run when
// the program is launched with "test" as its first argument.
void test_greet(void) {
    printf("[test] greet()\n");
    greet();
    printf("[test] passed: the line above should read \"Hello, World!\"\n");
}

int main(int argc, char *argv[]) {
    if (argc > 1 && strcmp(argv[1], "test") == 0) {
        test_greet();
        return 0;
    }
    greet();
    return 0;
}

Compile it with gcc and run the resulting binary:

gcc hello.c -o hello
./hello

That prints the greeting. Run the test instead by passing test as an argument:

./hello test

#include <stdio.h> pulls in the standard I/O library so printf is available, and #include <string.h> brings in strcmp for comparing the command-line argument. main is where execution begins; argc and argv carry the arguments the program was launched with, so checking argv[1] against "test" is how ./hello test is told apart from a normal run. return 0; tells the operating system the program finished successfully.

From here on, every step keeps its game logic in small functions like greet(), each with a matching test_<name>() next to it — no external testing framework, just plain C checked by eye or by a later assert(), all reachable through that same test argument.
