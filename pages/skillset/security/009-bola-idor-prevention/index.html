Broken Object Level Authorization (BOLA / IDOR)

BOLA / IDOR is #1 on the OWASP API Security Top 10: an authenticated user changes GET /invoices/1042 to GET /invoices/1043 and reads another customer?s data. Always scope repository queries by both the resource ID and the authenticated principal?s owner/tenant ID.

// VULNERABLE: Looks up the invoice by primary key alone ? any logged-in user can read any invoice!
@GetMapping("/invoices/{id}")
public InvoiceDto getInvoiceInsecure(@PathVariable UUID id) {
    return invoiceRepository.findById(id).map(InvoiceDto::from).orElseThrow();
}

// HARDENED: Enforces ownership in the SQL query itself + uses unguessable UUIDs
public interface InvoiceRepository extends JpaRepository<Invoice, UUID> {
    Optional<Invoice> findByIdAndOwnerId(UUID id, UUID ownerId);
}

@GetMapping("/invoices/{id}")
public InvoiceDto getInvoiceSecure(
        @PathVariable UUID id,
        @AuthenticationPrincipal Jwt jwt) {
    UUID currentUserId = UUID.fromString(jwt.getSubject());
    return invoiceRepository.findByIdAndOwnerId(id, currentUserId)
        .map(InvoiceDto::from)
        .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND));
}
