Path Traversal & Safe File Uploads

Using a client-supplied filename directly allows ../../etc/cron.d/pwn path traversal or executable script uploads. Ignore the client filename when storing on disk (generate a random UUID), verify Path.normalize().startsWith(baseDir), and check magic bytes.

public Path storeUploadedPdfSafely(Path baseUploadDir, MultipartFile file) throws IOException {
    if (file.getSize() > 10 * 1024 * 1024) {
        throw new IllegalArgumentException("File exceeds 10 MB limit");
    }

    // Verify PDF magic bytes (%PDF-) rather than trusting the client Content-Type header
    byte[] header = file.getInputStream().readNBytes(5);
    if (!Arrays.equals(header, "%PDF-".getBytes(StandardCharsets.US_ASCII))) {
        throw new SecurityException("Uploaded file is not a valid PDF");
    }

    // Generate an unguessable server filename and verify canonical containment
    String safeFileName = UUID.randomUUID() + ".pdf";
    Path target = baseUploadDir.resolve(safeFileName).normalize();
    if (!target.startsWith(baseUploadDir.normalize())) {
        throw new SecurityException("Path traversal attempt blocked");
    }
    Files.copy(file.getInputStream(), target, StandardCopyOption.REPLACE_EXISTING);
    return target;
}
