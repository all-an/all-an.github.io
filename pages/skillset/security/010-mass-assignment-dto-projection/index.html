Mass Assignment & DTO Boundary Projection

Binding incoming JSON directly to a JPA @Entity allows attackers to inject extra fields like {"role":"ADMIN","balance":999999} (Mass Assignment), and returning entities directly leaks internal fields like password hashes. Always use explicit Java record DTOs.

// VULNERABLE: Attacker sends {"username":"bob","role":"ADMIN","emailVerified":true}
@PostMapping("/users")
public User registerInsecure(@RequestBody User userEntity) {
    return userRepository.save(userEntity);
}

// HARDENED: Dedicated request & response records expose only the exact permitted fields
public record RegisterUserRequest(
    @NotBlank @Size(min = 3, max = 40) String username,
    @NotBlank @Email String email,
    @NotBlank @Size(min = 12, max = 128) String password
) {}

public record UserProfileResponse(UUID id, String username, String email) {
    public static UserProfileResponse from(User u) {
        return new UserProfileResponse(u.getId(), u.getUsername(), u.getEmail());
    }
}
