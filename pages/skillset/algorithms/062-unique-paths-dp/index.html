Unique paths (DP)

Medium Dynamic Programming

A robot starts at the top-left of an m × n grid and may only move right or down. How many distinct paths lead to the bottom-right corner? For a 3 × 7 grid there are 28.

Try it

↓

Approach

Any cell is reached either from the cell above or from the cell to its left, so paths[r][c] = paths[r − 1][c] + paths[r][c − 1]. The first row and first column each have exactly one path (straight along the edge).

Each row of the table depends only on the previous row, so a single array is enough: when you update paths[c] += paths[c − 1], paths[c] still holds the value from "above" and paths[c − 1] is already the new value "to the left".

Mathematically the answer is the binomial coefficient C(m + n − 2, m − 1): of the m + n − 2 moves, choose which m − 1 go down.

Java

// DP over one row: each cell = paths from above + paths from the left.
static int uniquePaths(int rows, int columns) {
    int[] paths = new int[columns];
    Arrays.fill(paths, 1); // the first row: one way to reach each cell
    for (int r = 1; r < rows; r++) {
        for (int c = 1; c < columns; c++) {
            paths[c] += paths[c - 1]; // paths[c] is "from above", paths[c - 1] "from the left"
        }
    }
    return paths[columns - 1];
}

JavaScript

// DP over one row: each cell = paths from above + paths from the left.
function uniquePaths(rows, columns) {
  const paths = new Array(columns).fill(1); // the first row: one way to reach each cell
  for (let r = 1; r < rows; r++) {
    for (let c = 1; c < columns; c++) {
      paths[c] += paths[c - 1]; // paths[c] is "from above", paths[c - 1] "from the left"
    }
  }
  return paths[columns - 1];
}

Complexity

  • Time O(m × n) — each cell is computed once
  • Space O(n) — a single row of the table

The follow-up adds obstacles: set the paths through a blocked cell to 0. The combinatorial formula gives O(min(m, n)) time but needs care with overflow.
