Lowest common ancestor (BST)

Medium Tree / BST

The lowest common ancestor (LCA) of two nodes is the deepest node that has both as descendants (a node counts as its own descendant). In a binary search tree the ordering lets you find it without searching the whole tree.

Try it

↓

Approach

Start at the root and compare both target values with the current node. If both are smaller, the LCA lies in the left subtree — move left. If both are larger, move right. Otherwise the values are on different sides (or one of them equals the current node), so this node is where the paths split: it is the LCA.

No recursion or extra memory is required, and it only ever descends one path. For a general binary tree (no ordering) you must search both subtrees and return the node where the two targets were found on different sides.

Java

static class TreeNode {
    int value;
    TreeNode left, right;
    TreeNode(int value) { this.value = value; }
}

// Walk down until p and q fall on different sides of the current node.
static TreeNode lowestCommonAncestor(TreeNode root, int p, int q) {
    TreeNode node = root;
    while (node != null) {
        if (p < node.value && q < node.value) node = node.left;        // both in the left subtree
        else if (p > node.value && q > node.value) node = node.right;  // both in the right subtree
        else return node;                                               // the paths split here
    }
    return null;
}

JavaScript

class TreeNode {
  constructor(value, left = null, right = null) {
    this.value = value;
    this.left = left;
    this.right = right;
  }
}

// Walk down until p and q fall on different sides of the current node.
function lowestCommonAncestor(root, p, q) {
  let node = root;
  while (node) {
    if (p < node.value && q < node.value) node = node.left;        // both in the left subtree
    else if (p > node.value && q > node.value) node = node.right;  // both in the right subtree
    else return node;                                               // the paths split here
  }
  return null;
}

Complexity

  • Time O(h) — one root-to-node path — O(log n) for a balanced tree
  • Space O(1) — iterative, no stack

Both target values must actually exist in the tree; if they might not, verify with a search first. The general-tree version runs in O(n) because without ordering there is no way to skip a subtree.
