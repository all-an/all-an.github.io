Course schedule (topological sort / cycle detection)

Medium–Hard Graph / Topological Sort

There are n courses, and some have prerequisites — "to take course 1 you must first take course 0". Can you finish them all? It is the same as asking whether the prerequisite graph has a cycle; if not, a valid order exists (a topological sort).

Try it

↓

Approach

Model courses as nodes and each prerequisite as a directed edge prerequisite → course. All courses can be finished exactly when the graph has no cycle. Kahn's algorithm checks this with a queue: compute each course's in-degree (how many prerequisites it still waits on), start with every course of in-degree 0, and repeatedly remove one, decrementing the in-degree of the courses that depended on it and queueing any that reach 0.

If you manage to remove all n courses, the order you removed them in is a valid schedule. If some are left over, they form (or depend on) a cycle, so the answer is false. A DFS with three colours (unvisited / in progress / done) detects cycles too.

Java

// Kahn's algorithm: peel off courses whose prerequisites are all done.
static boolean canFinish(int courseCount, int[][] prerequisites) {
    List<List<Integer>> dependents = new ArrayList<>();
    for (int i = 0; i < courseCount; i++) dependents.add(new ArrayList<>());
    int[] waitingOn = new int[courseCount]; // in-degree: prerequisites not yet taken
    for (int[] pair : prerequisites) {
        dependents.get(pair[1]).add(pair[0]); // edge: prerequisite -> course
        waitingOn[pair[0]]++;
    }
    Queue<Integer> ready = new ArrayDeque<>();
    for (int course = 0; course < courseCount; course++) {
        if (waitingOn[course] == 0) ready.add(course);
    }
    int taken = 0;
    while (!ready.isEmpty()) {
        int course = ready.remove();
        taken++;
        for (int next : dependents.get(course)) {
            if (--waitingOn[next] == 0) ready.add(next); // all its prerequisites are done
        }
    }
    return taken == courseCount; // leftovers mean a cycle
}

JavaScript

// Kahn's algorithm: peel off courses whose prerequisites are all done.
function canFinish(courseCount, prerequisites) {
  const dependents = Array.from({ length: courseCount }, () => []);
  const waitingOn = new Array(courseCount).fill(0); // in-degree: prerequisites not yet taken
  for (const [course, prerequisite] of prerequisites) {
    dependents[prerequisite].push(course); // edge: prerequisite -> course
    waitingOn[course]++;
  }
  const ready = [];
  for (let course = 0; course < courseCount; course++) {
    if (waitingOn[course] === 0) ready.push(course);
  }
  let taken = 0;
  while (ready.length > 0) {
    const course = ready.shift();
    taken++;
    for (const next of dependents[course]) {
      if (--waitingOn[next] === 0) ready.push(next); // all its prerequisites are done
    }
  }
  return taken === courseCount; // leftovers mean a cycle
}

Complexity

  • Time O(V + E) — each course and prerequisite is handled once
  • Space O(V + E) — the adjacency lists and in-degree array

The follow-up "Course Schedule II" asks for the order itself — just record courses as they leave the queue. Both are topological sorts, which also drive build systems and dependency resolvers.
