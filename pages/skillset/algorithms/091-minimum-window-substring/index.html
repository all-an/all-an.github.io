Minimum window substring

Hard Sliding Window

Given strings s and t, find the shortest substring of s that contains every character of t (with multiplicity) — for s = "ADOBECODEBANC" and t = "ABC" it is "BANC". The hardest classic sliding-window problem.

Try it

↓

Approach

Count how many of each character t needs, and track how many required characters are still missing. Expand the right edge of a window one character at a time; a character that is still needed reduces missing. Once missing reaches 0 the window is valid — record it if it is the shortest so far — then shrink from the left: drop the leftmost character, and if that makes a needed character short again, missing goes back above 0 and you resume expanding.

Each character enters and leaves the window at most once, so the search is linear. The count for a needed character goes negative when the window holds surplus copies, which is what lets the left edge safely skip them.

Java

// Sliding window: expand right until valid, then shrink left while it stays valid.
static String minWindow(String s, String t) {
    int[] needed = new int[128]; // remaining count needed per ASCII character
    for (char c : t.toCharArray()) needed[c]++;
    int missing = t.length();    // required characters not yet covered
    int left = 0, bestStart = 0, bestLength = Integer.MAX_VALUE;
    for (int right = 0; right < s.length(); right++) {
        if (needed[s.charAt(right)]-- > 0) missing--; // a still-needed character was covered
        while (missing == 0) {                        // the window is valid: try to shrink it
            if (right - left + 1 < bestLength) {
                bestLength = right - left + 1;
                bestStart = left;
            }
            if (++needed[s.charAt(left++)] > 0) missing++; // we dropped a needed character
        }
    }
    return bestLength == Integer.MAX_VALUE ? "" : s.substring(bestStart, bestStart + bestLength);
}

JavaScript

// Sliding window: expand right until valid, then shrink left while it stays valid.
function minWindow(s, t) {
  const needed = new Map(); // remaining count needed per character (negative = surplus in the window)
  for (const char of t) needed.set(char, (needed.get(char) || 0) + 1);
  let missing = t.length;   // required characters not yet covered
  let left = 0;
  let bestStart = 0;
  let bestLength = Infinity;
  for (let right = 0; right < s.length; right++) {
    if (needed.has(s[right])) {
      if (needed.get(s[right]) > 0) missing--; // a still-needed character was covered
      needed.set(s[right], needed.get(s[right]) - 1);
    }
    while (missing === 0) {                    // the window is valid: try to shrink it
      if (right - left + 1 < bestLength) {
        bestLength = right - left + 1;
        bestStart = left;
      }
      if (needed.has(s[left])) {
        needed.set(s[left], needed.get(s[left]) + 1);
        if (needed.get(s[left]) > 0) missing++; // we dropped a needed character
      }
      left++;
    }
  }
  return bestLength === Infinity ? '' : s.slice(bestStart, bestStart + bestLength);
}

Complexity

  • Time O(n + m) — both window edges only ever move right
  • Space O(k) — k distinct characters in t (O(1) for ASCII)

The single missing counter is the key optimisation: comparing two full count maps on every step would make each window check O(k) instead of O(1).
