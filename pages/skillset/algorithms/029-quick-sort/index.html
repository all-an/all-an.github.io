Quick sort

Easy–Medium Sorting / Divide & Conquer

Quick sort picks a pivot, partitions the array into elements smaller and larger than it, and recursively sorts the two sides. It is usually the fastest general-purpose sort in practice, and sorts in place.

Approach

Partition: choose a pivot (here the last element). Sweep through the range, moving every element smaller than the pivot to the left part; finally swap the pivot into the slot right after them. The pivot is now in its final sorted position. Recurse: sort the part to its left and the part to its right independently.

Pivot choice is the whole game. Always taking the last element degrades to O(n²) on already-sorted input; picking a random element (or median of three) makes the bad case vanishingly unlikely.

Java

// Quick sort in place, using the Lomuto partition scheme.
static void quickSort(int[] numbers, int low, int high) {
    if (low >= high) return; // zero or one element: sorted
    int pivotIndex = partition(numbers, low, high);
    quickSort(numbers, low, pivotIndex - 1);
    quickSort(numbers, pivotIndex + 1, high);
}

// Move everything smaller than the pivot (last element) to the left; return the pivot's final index.
static int partition(int[] numbers, int low, int high) {
    int pivot = numbers[high];
    int boundary = low; // everything before boundary is < pivot
    for (int i = low; i < high; i++) {
        if (numbers[i] < pivot) {
            swap(numbers, i, boundary++);
        }
    }
    swap(numbers, boundary, high); // put the pivot in its final place
    return boundary;
}

static void swap(int[] numbers, int a, int b) {
    int temp = numbers[a];
    numbers[a] = numbers[b];
    numbers[b] = temp;
}

JavaScript

// Quick sort in place, using the Lomuto partition scheme.
function quickSort(numbers, low = 0, high = numbers.length - 1) {
  if (low >= high) return numbers; // zero or one element: sorted
  const pivotIndex = partition(numbers, low, high);
  quickSort(numbers, low, pivotIndex - 1);
  quickSort(numbers, pivotIndex + 1, high);
  return numbers;
}

// Move everything smaller than the pivot (last element) to the left; return the pivot's final index.
function partition(numbers, low, high) {
  const pivot = numbers[high];
  let boundary = low; // everything before boundary is < pivot
  for (let i = low; i < high; i++) {
    if (numbers[i] < pivot) {
      [numbers[i], numbers[boundary]] = [numbers[boundary], numbers[i]];
      boundary++;
    }
  }
  [numbers[boundary], numbers[high]] = [numbers[high], numbers[boundary]]; // pivot to its final place
  return boundary;
}

Complexity

  • Time O(n log n) — on average; O(n²) in the worst case
  • Space O(log n) — recursion stack on average (in-place partitioning)

Quick sort is not stable. Many equal keys also slow the Lomuto scheme, so production versions use three-way partitioning (less / equal / greater). Java's primitive Arrays.sort uses a dual-pivot quick sort.
