Binary search on answer (e.g., capacity to ship)

Medium–Hard Binary Search

Some problems ask for the smallest (or largest) value that satisfies a condition, and that condition flips exactly once as the value grows. Instead of searching an array, you binary-search the range of possible answers. The classic example: find the least ship capacity that delivers all packages within D days.

Approach

First bound the answer: the capacity must be at least the heaviest package (or that package could never ship) and at most the total weight (everything in one day). Then binary-search that range. For a candidate capacity, a simple feasibility check loads packages in order, starting a new day whenever the next one would overflow, and counts the days. If it fits in D days, the candidate might be the answer (or something smaller works) — search lower; otherwise search higher.

The template generalises to any monotonic yes/no question: "koko eating bananas", "split array largest sum", "minimum days to make bouquets". Write the isFeasible function first; the search around it is always the same.

Java

// Binary search over the answer: the smallest capacity that ships everything within 'days'.
static int shipWithinDays(int[] weights, int days) {
    int low = 0;    // smallest possible: the heaviest package
    int high = 0;   // largest needed: everything in one day
    for (int weight : weights) {
        low = Math.max(low, weight);
        high += weight;
    }
    while (low < high) {
        int middle = low + (high - low) / 2;
        if (daysNeeded(weights, middle) <= days) high = middle; // feasible: try smaller
        else low = middle + 1;                                  // too small: go bigger
    }
    return low;
}

// Feasibility check: how many days does a ship of this capacity need?
static int daysNeeded(int[] weights, int capacity) {
    int days = 1;
    int load = 0;
    for (int weight : weights) {
        if (load + weight > capacity) { // this package starts a new day
            days++;
            load = 0;
        }
        load += weight;
    }
    return days;
}

JavaScript

// Binary search over the answer: the smallest capacity that ships everything within 'days'.
function shipWithinDays(weights, days) {
  let low = Math.max(...weights);                            // smallest possible: the heaviest package
  let high = weights.reduce((total, w) => total + w, 0);     // largest needed: everything in one day
  while (low < high) {
    const middle = Math.floor((low + high) / 2);
    if (daysNeeded(weights, middle) <= days) high = middle;  // feasible: try smaller
    else low = middle + 1;                                   // too small: go bigger
  }
  return low;
}

// Feasibility check: how many days does a ship of this capacity need?
function daysNeeded(weights, capacity) {
  let days = 1;
  let load = 0;
  for (const weight of weights) {
    if (load + weight > capacity) { // this package starts a new day
      days++;
      load = 0;
    }
    load += weight;
  }
  return days;
}

Complexity

  • Time O(n log S) — S is the size of the answer range; each probe scans all n packages
  • Space O(1) — only a few variables

The classic mistake is an off-by-one in the loop: with low < high and high = middle (not middle − 1) the search converges on the first feasible value without skipping it.
