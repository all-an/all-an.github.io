Aggregation

An association that adds a whole-part reading, but a weak one: the whole groups the parts without owning them. The part is created elsewhere, can belong to several wholes at once, and survives the whole's destruction — a team has players, but deleting the team does not delete the people.

A held reference with weak ownership (Java, C#, C++), a hollow diamond in UML notation, has-a (weak) in general OOP — the part's lifecycle is independent.

The parts arrive from outside, already alive. The team stores what it was given and claims nothing about how long they live:

class Team {
    private final List<Player> players;   // Team ◇──> Player

    Team(List<Player> players) { this.players = players; }   // passed in, not created here
}

Which means the same part can sit in two wholes, and outlives both:

Player ana = new Player("Ana");
Team club    = new Team(List.of(ana));
Team country = new Team(List.of(ana));   // same object, two wholes

club = null;                             // ana is untouched

The cost: shared parts mean shared mutation. Store the caller's list and they can still modify it behind your back; hand yours out and they can too — so copy the collection on the way in and wrap it on the way out. The distinction from composition is also a design claim, not something the compiler checks: in Java both look like a field, and only C++'s T* versus unique_ptr<T> makes it explicit.
